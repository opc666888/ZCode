# Claude 360 发版铁律：绝不能让客户的 Claude 泄露

> owner 2026-11-27 定，**所有改动永久适用**（不是某一次需求）。Review 和发版测试都按这一页过，过不了就不发。
> 原话：「绝对不能让已经在用的用户因为我们的 bug 导致 DNS 泄露，让那个 Claude 泄露……批量的人账号被封了，那是多大风险啊？……升级一定要有兼容性……一定要做好测试，就是做升级的测试。」

## 为什么

线上已经有在用的客户。客户的 Claude 只要有一次请求（或一次 DNS 查询）没走我们给的美国静态 IP、直接从本地网络出去，号就可能被封。一个 bug 跟着升级包发出去，就是**一批客户一起被封**。这是最高等级事故，优先级高于任何功能和上线时间。

适用范围：Claude 360 Code（本仓库）、Claude 360 Manager（exclusive-env 仓库）、接管层、热更新包、服务端下发的配置与规则——只要会跑到客户电脑上的东西都算。

## Review 必查（每个改动都要回答，写进提交说明或回执）

| # | 问题 | 不合格的例子 |
|---|---|---|
| 1 | 这次改动碰没碰网络路径？（系统代理、TUN/接管、DNS、路由、出口选择） | 改了接管规则顺序、改了代理端口、加了新网卡判断 |
| 2 | 有没有改 Claude Code / 浏览器 / 指纹浏览器的启动方式或环境变量？（`HTTP(S)_PROXY`、`NO_PROXY`、`ALL_PROXY`、`CLAUDE_CODE_*`、`NODE_OPTIONS`、HOME、配置目录） | 给子进程清空了环境变量、新加 `NO_PROXY=*` |
| 3 | 有没有新增对外请求？请求的是谁、走哪条路？ | 新加的检查直接用 Node 原生 socket 绕过系统代理、请求 Anthropic 域名 |
| 4 | 失败时怎么兜底？接管没起来 / 内核挂了 / 规则下载失败时，Claude 会不会退回本地网络直连？ | 「代理连不上就直连」这类回退 |
| 5 | 老版本升上来兼容吗？（旧配置、旧数据目录、旧接管层版本、Windows / Mac 各一遍） | 新版读不到旧配置就用默认值，默认值不走代理 |

只要 1–4 任一条回答「碰了」，就必须做下面「碰网络的额外测试」。**原则是 fail-closed**：网络不对就让 Claude 用不了，绝不能让它悄悄走本地网络。

## 发版前必做测试：覆盖升级 + 泄露核对

1. 测试电脑（macmacbook-pro，Intel）装的是**线上现行版本**，网络已接管。
2. 升级前跑 `zsh scripts/c360/leak-check.sh <该机静态 IP>`（经 SSH：`ssh … 'zsh -s <IP>' < scripts/c360/leak-check.sh`），结果存档，必须 `RESULT PASS`。
3. **真正退出旧版**再覆盖：`kill -TERM <主进程>`，用 `pgrep -x "Claude 360 Code"` 核对进程号确实变了（osascript quit 经 SSH 不生效，11-27 踩过：旧进程没退，等于没测）。
4. 装新版、启动，核对：数据目录还在（`~/.claude360code` 文件数不减）、当天日志没有 error、Agent 就绪。
5. 升级后再跑一次 leak-check：必须 `RESULT PASS`，且出口 IP、DNS 结果和升级前一致。
6. 有 Windows 包的，Windows 云电脑同样走一遍（测完在控制台关机）。

脚本检查的是：生效系统代理端口有人在听、不走代理 / 走系统代理 / 清空环境变量三条路出口一致且都是期望的美国静态 IP、`claude.ai` `api.anthropic.com` `statsig.anthropic.com` 都由接管层解析（198.18.0.0/15 假地址）、接管网卡在。任何一项 FAIL 都不许发。

## 碰网络的额外测试

- 在 owner 提供的测试号上真机发一条消息，同时在测试电脑上核对 Claude Code 进程的连接全部走接管（不登 owner 本人的号，见 `no-owner-account-on-test-mac`）。
- 故意制造失败：停掉接管内核 / 拔掉规则，确认 Claude 是「连不上」而不是「走本地网络连上了」。
- Mac、Windows 都要测。
